# Аудит текущего кода

Что система меняет относительно репозитория `inkoffTTV/Vicinity` (ветка main, октябрь 2026) и почему. Значения — из `web/src/theme.css`, `web/src/styles.css`, `web/src/lib/themes.ts`, `client/src/core/ThemeManager.*`, `client/qml/**`.

## Что уже хорошо

- Панели-карточки с зазором 8px на земле и градиентные темы — это и есть характер Vicinity; система его закрепляет, а не меняет.
- Токены палитры в `theme.css` уже разведены по четырём базовым темам и модификаторам (`data-contrast`, `data-saturation`); акцент под цветовую тему вычисляется, а не выбирается вручную.
- Onest + Unbounded — удачная пара с разными ролями.
- Одна кривая анимации `cubic-bezier(0.2, 0.8, 0.2, 1)` используется почти везде; `reducedMotion` есть в обоих клиентах.

### 🟢 Полировка

- `rail-item` при активации меняет радиус 14 → 12 на наведении; система фиксирует `radius-md` для кнопки и `radius-pill → radius-md` для перехода «неактивный → активный» (как в превью ServerRail).
- Разделители дат и «Непрочитанные» нарисованы разными способами; система даёт один компонент `UnreadDivider` на оба случая.
- Тосты лежат на `--bg-raised`, который в градиентной теме полупрозрачный; система даёт тостам `bg-modal` + `shadow-modal`.
- Моноширинный шрифт для кода не задан явно (падает в системный); система добавляет семейство `mono`.

## Не вошло в систему

- Компонентный бандл (`components/bundle.js`) не собирался — превью написаны вручную по `web/src/components/*.tsx` и работают как спецификация, а не как сборка библиотеки. Сборка из `web/` возможна по запросу.
- Градиентные цветовые темы (`COLOR_THEMES`, 24 штуки) — не токены, а данные пользовательской настройки; они остаются в `lib/themes.ts` и в этой системе описаны правилом, а не значениями.
- Иконки (`Icon.tsx`) — встроенные SVG-пути внутри компонента, отдельных файлов нет; в `assets/` скопирован только знак `favicon.svg`.
